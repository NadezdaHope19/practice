# Кратко описание логики БД
## Регистрация пользователя
### users
Таблица users хранит пользователей платформы.  
Связь с таблицей privacy_policies: храним информацию о том, какая версия офферты и согласия на обработку данных была подписана при регистрации.  
Важное ограничение: phone_number должен быть уникальным, один аккаунт на один номер телефона. status_user может быть "активен" только у блогера (is_blogger=true), если у него есть запись со статусом "верифицирована" в таблице user_platforms и запись в таблице subscriptions со значением ended_at больше текущей даты (активная подписка).  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| user_id  | uuid | PK | not null, unique | первичный ключ |
| privacy_id | integer | FK | not null | связь с таблицей privacy_policies |
| user_name | varchar(200) | | not null | имя пользователя |
| phone_number | varchar(15) | | not null, unique | телефон, на который зарегистрирован аккаунт |
| registred_at | timestamptz | | | дата регистрации аккаунта |
| is_blogger | boolean | | | роль "блогер" |
| is_seller | boolean | | | роль "селлер" |
| status_user | enum | | | статус аккаунта: "создан", "активен", "заблокирован" |
| rating_avg | numeric(3, 2) | | | средний рейтинг |
| rating_count | integer | | | количество оценок пользователя |
| blocked_at | timestamptz | | | дата блокировки пользователя |
### privacy_policies
Таблица privacy_policies хранит офферты и согласия об обработке данных, которые действовали на момент регистрации.  
Связь с таблицей users: одну офферту могут подписать несколько пользователей.  
Важное ограничение: created_at по умолчанию текущее время и дата при создании записи, is_active=true не больше одной записи в таблице.  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| privacy_id | integer | PK | not null, unique | первичный ключ |
| version | varchar(20) | | not null, unique | номер версии офферты |
| offer_text | text | | not null | текст офферты |
| consent_text | text | | not null | текст согласия |
| created_at | timestamptz | | not null | дата публикации офферты |
| is_active | boolean | | default true, limit 1 | актуальность документов |

## Селлер создает рекламмную кампанию
### campaigns
Таблица campaigns хранит все рекламмные кампании (РК), которые создают селлеры.  
Связь: 
- с users: одна кампания, один user_id, но у одного user_id может быть несколько кампаний;
- с topics: одна кампания, один topic_id.

Важное ограничение: удаление кампании "мягкое", budget максимальное значение 500000 руб.  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| campaign_id  | uuid | PK | not null, unique | первичный ключ |
| seller_id | uuid | FK | not null | создатель РК, связь с users |
| topic_id | integer | FK | not null | тема РК, связь с topics |
| description | text | | not null | описание РК |
| budget | numeric(8, 2) | | not null, max 500000 руб  | бюджет РК |
| settings | JSONB | | | гибкие настройки РК |
| payment_type | varchar(20) | | not null | тип оплаты |
| status_campaign | enum | | not null | текущий статус кампании: "подготовка", "в поиске", "на паузе", "в работе", "завершена", "отменена" |
| created_at | timestamptz | | not null | дата создания кампании |
| deleted_at | timestamptz | | | дата удаления кампании |

## Блогер заполняет профиль
### user_platforms
Таблица user_platforms хранит все добавленные платформы блогерами.  
Связь:
- со справочниками audience и reach: у одной платформы может быть один диапазон из справочника.
- с таблицей topics: у одной платформы может быть несколько тематик (связь через промежуточную таблицу topic_user_platform).

Важное ограничение: у одного user_id может быть несколько разных платформ, у одного platform_id не может быть добавлено больше 10 тематик блога, удаление записей "мягкое", не может быть удалена единственная верифицированная запись.  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| platform_id  | uuid | PK | not null, unique | первичный ключ |
| blogger_id | uuid | FK | not null | блоггер, владелец соцсети, связь с users |
| audience_id | integer | FK | not null | связь со справочником кол-ва аудитории audience |
| reach_id | integer | FK | not null | связь со справочником кол-ва охвата reach |
| platform | enum | | not null  | платформа: "Instagram", "Telegram", "TikTok", "YouTube", "VKontakte", "Dzen" |
| social_link | varchar() | | not null | ссылка на аккаунт |
| region | enum | | not null | регион: "Россия", "мир", "Казахстан" |
| status | enum | | not null | статус записи: "не верифицирована", "верифицирована", "на проверке" |
| created_at | timestamptz | | not null | дата добавления платформы |
| deleted_at | timestamptz | | | дата удаления платформы |

### topics
Таблица topics хранит тематики используемые при заполнении своих соцсетей.  
Связь: 
- c таблицей user_platform: у одной соцсети может быть несколько тематик, cвязь многие ко многим организуем через промежуточную таблицу topic_user_platform;
- c таблицей campaigns: один к одному.

| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| topic_id | integer | PK | not null, unique | первичный ключ |
| topic_name | varchar(50) | | not null, unique | наименование тематики |

## Система отправляет оффер блогеру
### offers
Таблица offers хранит сведения обо всех сформированных системой офферов. Принято решение хранить офферы отдельно от сделок, чтобы не перегружать таблицу сделок отклоненными офферами, недошедшими до статуса сделки.  
Связь:

- c таблицей deals: у одного оффера может быть только одна сделка;
- с таблицей campaigns: у одной кампании может быть несколько офферов;
- с таблицей users: у одного пользователя с ролью блогер может быть несколько офферов.  
Важное ограничение: оффер в статусе "создан", "отклонен", "просрочен", "отменен" не может иметь связь со сделкой.  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| offer_id  | uuid | PK | not null, unique | первичный ключ, связь с deals |
| campaign_id | uuid | FK | not null | связь с campaigns |
| blogger_id | uuid | FK | not null | блогер, которому направлен оффер, связь с users |
| status_offer | enum | | not null | статус оффера: "создан", "ожидает подтверждения", "отклонен", "просрочен", "отменен" |
| created_at | timestamptz | | not null  | дата и время создания оффера |
| ended_at | timestamptz | | not null | дата и время истечения оффера |

### deals
Один оффер - одна сделка, связь один к одному по id_оффера, поле is_safe_deal для безопасных сделок, поля campaign_id и blogger_id дублируем для удобства отображения актуальных сделок, чтобы не использовать сложные запросы

## Safe-сделка и платеж
### safe_deal_payments
Безопасная сделка - поле is_safe_deal в таблице deals. Связь с таблице deals один ко многим, потому что предусмотрена повторная оплата, в случае неудачи. Храним количество попыток оплаты, код ошибки от системы и текст ошибки. Внешний payment_id для идентификации платежа, должен быть уникальным, чтобы не списать оплату дважды. Payment_method - все системы предусмотренные для оплаты (enum).

## Промокоды
### promos
Таблица promos хранит все промокоды применяемые к подпискам.  
Связь c таблицей subscriptions: один промокод может быть применен в нескольких подписках.  
Важное ограничение: один промокод может быть применим к выбранным тарифам указанным в массиве template_ids, если в массиве не указан ни один тариф, значит промокод распространяется на все тарифы.    
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| promo_id  | integer | PK | not null, unique | первичный ключ |
| code | varchar(30) | | not null | текст промокода |
| template_ids | integer[] | | not null | список тарифов к которым применим промокод |
| created_at | timestamptz | | not null | время и дата создания |
| starts_at | timestamptz | | not null  | время и дата начала действия |
| ends_at | timestamptz | | not null | время и дата окончания действия |
| is_active | boolean | | not null, default true | активность промокода |
| limit | integer | | | ограничение по количеству применений |
| rules | JSONB | | not null | условия применения промокода |

## Файлы
### files
Таблица files хранит информацию обо всех загруженных файлах пользователей.  
Связь:

- с таблицей users: файлы принадлежат конкретному пользователю, у одного пользователя несколько файлов;
- с таблицей campaigns: к кампании может быть прикреплено несколько файлов, один файл может быть использован в нескольких кампаниям пользователя (связь многие ко многим через промежуточную таблицу files_campaign).  
Важное ограничение: Файл грузим в облако, храним на него ссылку в storage_path.  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| file_id  | uuid | PK | not null, unique | первичный ключ, связь с files_campaign |
| user_id | uuid | FK | not null | кому принадлежат файлы, связь с user |
| storage_path | varchar() | | not null |  |
| file_name | varchar(255) | | not null | имя файла |
| file_type | varchar(16) | | not null | тип файла |
| file_size | integer | | not null | размер в байтах |
| uploaded_at | timestamptz | | not null | время и дата загрузки файла |

## Отзывы
### reviews
Таблица reviews хранит все отзывы с оценками по сделке
Связь с таблицей deals: один ко многим, отзыв может оставить как селлер, так и блогер. 
Важное ограничение: каждая сторона может оставить не более одного отзыва (составной ключ deals_id,user_id). Храним оценку rating, пересчитываем rating_avg и rating_count в таблице users один раз в сутки процедурой или реализуем триггер в момент вставки. Отзыв может быть написан только сторонами, которые участвовали в сделке. Отзыв может быть написан только к сделке в статусе
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| review_id  | integer | PK | not null, unique | первичный ключ |
| deal_id | uuid | FK | not null | к какой сделке относится, связь с deals |
| author_id | uuid | | not null | автор отзыва |
| recepient_id | uuid | | not null | получатель отзыва |
| rating | integer | | not null | оценка взаимодействия по 5-тибалльной |
| comment | text | | not null | текст отзыва |
| created_at | timestamptz | | not null | время и дата создания отзыва |

## Сообщения и уведомления
Сообщения и уведомления разделены, чаты необходимо хранить длительно, после завершения сделки, они жестко связаны с таблицей deals.
### notifications
В таблице notifications храним все уведомления направляемые пользователям.  
Связь с таблицей users: у одного пользователя может быть много оповещений.  
Важное ограничение: в таблице поля entity_name и entity_id чтобы из уведомления по сделке или офферу можно было сразу перейти на нужную страницу.  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |
|:--------:|:----:|:----:|:--------------------:|:----------:|
| notification_id  | integer | PK | not null, unique | первичный ключ |
| recepient_id | uuid | FK | not null | получатель уведомления, связь с users |
| text | text | | not null | текст уведомления |
| created_at | timestamptz | | not null | время и дата создания уведомления |
| entity_name | varchar(50) | | | относится к указанной сущности |
| entity_id | uuid | | | относится к указанной записи |
| is_read | boolean | | default false | уведомление прочитано? |

### messages
Таблицу messages хранит все сообщения по сделкам.  
Связь с таблицей deals: через промежуточную таблицу chats, для реализации в случае разбора спора и необходимости подключения третьей стороны, потребуется создать еще чаты с продавцом и блогером, которые должны быть привязаны к сделке.  
| Имя поля | Тип  | Ключ | Условия, ограничения | Назначение |

| author_id | uuid | | not null | автор сообщения |
| text | text | | not null | текст сообщения |

| is_read | boolean | | default false | сообщение прочитано? |
